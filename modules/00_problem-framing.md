# Module 00: 문제 정의 (Problem Framing)

## 목적
사용자가 제시한 문제가 '진짜 문제'인지 검증하고,
해결 가능한 형태의 질문으로 재구성한다.
잘못 정의된 문제는 이후 5단계 전체를 오염시킨다.

## 주력 방법론
- 5 Whys (도요타 오노 다이이치, Toyota Production System, 1978):
  표면 문제 → 근원 문제 소급
- 드러커식 질문 재구성 (Drucker, The Effective Executive, 1967):
  "올바른 답보다 올바른 질문" — 문제를 과제(task)가 아닌
  목적(purpose)으로 환원

## 예비 방법론
- Cynefin 간이 판별 (Snowden, HBR 2007 — 유형 분류에만 차용):
  정형 / 복잡 / 긴급

## 원인 탐색 방식 분기 (유형별)
- 정형: 5 Whys 단선 소급 (원인 경로 1개면 충분)
- 복잡: Why Tree 다분지 소급 — 각 Why 단계에서 복수 원인 분기 허용
- 긴급: 원인 탐색 최소화, 즉시 대응책과 사후 원인분석 분리
- 공통: 도출된 모든 원인은 '확정'이 아닌 가설(H1, H2...)로
  라벨링 → 02에서 검증

## 실행 절차
1. **표면 문제 기록**: 사용자 표현 그대로 1문장 정리
2. **Whys 소급**: 최대 5회 "왜" 반복. 기계적 5회가 아니라
   '조직(또는 사용자)이 통제 가능한 원인'에 도달하면 중단
3. **문제 재정의**: "어떻게 하면 ~할 수 있는가(HMW)" 형식의
   해결 지향 질문 1개 확정
4. **범위 확정**: 포함/제외 경계 명시 (scope in/out)
5. **성공 기준 정의**: 해결됐다고 판단할 측정 가능 기준 1~3개
   (03 Working Backwards와 04 가중치 도출의 기점이 됨)
6. **정보 갭 처리**: 모르는 것은 임의판단 금지 →
   Phase A 미확보분은 [가정 An] 라벨로 전환 후 계속 진행
   (실행 중 사용자 질문 금지, 최종 보고서 부록에 일괄 수록)

## 산출물 (개조식)
## 【문제 정의서】
### 1. 표면 문제 vs 근원 문제 (Whys 경로 — 들여쓰기 개조식)
### 2. 재정의된 문제 (HMW 1문장)
### 3. 문제 유형·성격 및 범위 (in/out)
### 4. 성공 기준
### 5. 가설 목록 (H1, H2... — 모두 가설 라벨)
### 6. 정보 갭·가정 목록 (부록 이월용 — 여기서 실행 중단 금지)

## 조직 맥락 체크포인트
- 규정·법령·내부 정책상 이미 답이 정해진 사안인지 선확인
- 문제의 소유자(주무부서)와 사용자의 권한 범위 구분
- 상위 평가·감사 체계가 있는 조직이면, 그 관점에서 문제 방치 시
  리스크 여부 점검

## 금지 사항
- 사용자가 가져온 해결책을 문제로 오인하지 말 것
  (예: "PPT 만들어야 해" → 진짜 문제는 "경영진 설득")
- 근거 없는 원인 추정으로 Whys를 채우지 말 것
- 가설을 확정 원인처럼 서술하지 말 것
