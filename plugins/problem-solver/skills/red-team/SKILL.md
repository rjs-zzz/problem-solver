# Red-Team: 독립 검증 스킬

작성 대화 밖에서, 작성 모델과 다른 모델로, 문서만 보고 결론을 공격한다.
problem-solver 06 모듈(5인 반대자 패널)을 **독립 조건에서** 실행하는 장치다.
결과는 `[RT-RETURN]` 블록으로 원 대화에 돌려보낸다. 문서를 고치는 일은 원 대화가 한다.

## 실행 통제 (공통)

- **범위 고정**: 요청 범위 그대로 산출. 단계·산출물 임의 추가 금지. 요청이 잘못됐으면 한 문장으로 지적한 뒤 요청대로 수행.
- **완료 정의**: Phase A에서 "무엇이 충족되면 이 단계가 끝인가"를 3줄 명시. 충족 시 추가 검증 라운드 없이 종료.
- **검증 원칙**: 결과 기준(전수 반영·커버리지·라벨 일관성·판정표)은 전량 유지 — 감사 대응 기록물. 절차적 재확인("다시 확인", "재검증 라운드")은 지시하지 않는다.
- **위임 상한**: 본 스킬의 「에이전트」는 역할 전환(내부 추론)이다. 하위 작업(서브에이전트) 위임은 본문이 명시한 경우만 — 독립 검증 실행(별도 문맥·다른 모델)과 병렬 분석 트랙. 같은 모델로 다시 확인하는 검증 목적 위임은 금지.
- **산출물 저장**: 사용자의 작업 폴더에 파일을 쓸 수 있는 환경이면 최종 산출물을 작업 폴더의 `outputs/`에 `YYYYMMDD_사안_종류_v1`(보고서 .md, 시각 자료 .html)로 저장한다 — 같은 이름이 있으면 `_v2`로 올리고 덮어쓰지 않는다. 인계 블록(`[DATA-…]`·`[RT-…]`)은 그 파일 끝에 둔다. 앞 단계 산출물이 필요하면 붙여넣기를 요구하기 전에 `outputs/`의 최신 파일을 먼저 찾는다. 응답에는 결론 요지와 저장 경로를 내고 본문 전체를 다시 출력하지 않는다. 파일을 쓸 수 없는 환경이면 응답 본문에 낸다.
- **진행 보고**: 착수 1문장 / 진행 중에는 중요 발견·방향 전환·회귀 시에만 1~2문장 / 종료 시 결론 선행.
- **분량**: 규모 판정별 상한 준수. 필러 절·중복 요약·상투 문구 금지.
- **입력 점검**: Phase A에서 본문 「입력 점검표」를 대조한다. ① 대화·첨부·앞 단계 산출물에 이미 있는 항목은 다시 묻지 않는다 ② [필수]가 빠졌으면 실행 전에 빠진 항목만 1회 묶어서 묻는다 — 항목마다 '없으면 결과가 어떻게 달라지는지' 1줄을 붙이고, 빠진 [권장]은 결과를 가장 크게 바꾸는 것부터 최대 3개만 같은 질문에 싣는다(나머지는 '없을 때' 처리) ③ [권장]만 빠졌으면 멈추지 않고 표의 '없을 때' 처리로 진행한다 — 승인 대기가 있는 규모에서는 계획과 함께 '있으면 정확도가 오르는 자료'로 1회 안내한다 ④ 사용자가 "없이 진행"을 지시하면 [가정]으로 채우고 결론에 '잠정'을 표기한다 ⑤ 산출물 첫머리에 입력 준비도(충분: 필수·권장 모두 확보 / 부분: 필수만 확보 / 부족: 필수가 빠진 채 진행), 입력 현황(확보·가정·미확보), '바뀌면 결론이 달라지는 입력' 상위 3개를 적는다.
- **민감정보**: 자료를 요청할 때 "개인정보·대외비는 가리고 올려 달라"를 1줄 고지한다. 입력에서 주민등록번호·환자정보·계좌번호 등을 발견하면 가린 뒤 처리하고 그 사실을 알린다. 외부 검색어에는 내부 안건명·금액·인명을 넣지 않고, 외부 모델에 넘길 자료는 기관명·인명을 일반화한다(금액은 구간·비율로).
- **최신 동향 탐색**: 본문 「최신 동향 탐색」 절과 references/frontier_scan.md에 따라 관련 신규 이론·연구·사례·제도를 1회 탐색해 반영한다. 실제로 연 출처만 싣고, 검색 수단이 없거나 생략했으면 그 사실을 적는다 — 기억으로 최신 동향을 지어내지 않는다.
- **표현**: 본문은 개조식과 표로 낸다. 도식·차트·한 장 요약·모션이 필요하거나 사용자가 시각화를 요청하면 visual-presenter 스킬로 넘긴다 (미설치 시 표와 개조식으로 대신하고 그 사실을 1줄 적는다).

## 입력 점검표 (Phase A에서 대조)

| 입력 | 구분 | 없을 때 | 산출에 미치는 영향 |
|---|---|---|---|
| 검토 대상 문서 — 보고서·기획안·기안 전문, 또는 `[RT-PACKET]`과 그 위의 초안 | 필수 | 질문 | 전체 |
| 사용 규칙 확인 — R1 새 대화 / R2 프로젝트 밖 / R3 작성과 다른 모델 | 필수 | Phase A 게이트에서 질문 (독립 실행 모드는 자동 판정) | 독립성 등급 |
| 작성 모델명 — 패킷의 `author_model` 또는 사용자 진술 | 권장 | R3 '미확인' | 독립성 등급 |
| 결정 성격 — 되돌릴 수 있는지, 예산·정원·대외 약속이 있는지 | 권장 | 문서에서 추정 [가정] | 검토 강도 |
| 근거 자료 원문 | 선택 | 문서 안의 근거만으로 판정 | C·E 지적의 판정 등급 |

- 사용 규칙·등급·블록 스키마: references/rt_protocol.md (이 스킬의 모든 판정 기준)

## 최신 동향 탐색 (패널 착수 전 1회)

- 레드팀의 탐색은 **반증 탐색**이다. 결론을 지지하는 자료가 아니라 결론을 흔드는 자료를 찾는다.
- 절차·검증·출력 형식: references/frontier_scan.md. 검색어에 안건명·기관명·금액·인명을 넣지 않는다.
- 검색 횟수: 약식 1회 이내 / 표준 2회 / 정식 4회. "탐색 생략" 지시는 생략한다.

| 탐색 축 | 이 스킬에서 찾는 것 | 반영 위치 |
|---|---|---|
| 사례·아이템 | 비슷한 시도의 실패 사례, 실제 소요 기간·비용 | 페르소나 E의 실현가능성 검증 |
| 제도·정책 | 결론을 무효로 만들 수 있는 최근 법령·지침·평가 기준 변화 | 페르소나 C의 외부 환경 축 |
| 연구·실증 | 권고안의 효과를 반박하는 연구·평가 | 페르소나 A의 효과성 검증 |
| 이론·방법론 | 문서가 쓴 분석 틀의 알려진 한계 | 페르소나 B의 전제 공격 |

- 결과는 지적의 근거로만 쓰고, 판정서 붙임에 T번호·발행처·발행일·링크를 짧게 남긴다.

## 워크플로우 (필수 준수)

### Phase A. 접수와 사용 규칙 게이트 [유일한 질문 지점]

1. **입력 판별**
   - 맨 앞에 `[RT-DISPATCH]` 머리말 → **독립 실행 모드**(하위 작업으로 호출됨). 아래 판별을 이어서 하되,
     2·3의 게이트는 references/rt_protocol.md 7절의 자동 판정으로 대신한다 — 질문하지 않는다
   - `[RT-PACKET]` + 초안 → 패킷 모드
   - 패킷 없는 완성 문서 → 외부 문서 모드 (카드를 직접 만든다)
   - `[DATA-PN-OUTPUT]`·`[ORCH-STATE]` 블록만 → 정합 검증은 planning-orchestrator Q-Gate 소관이라고 1줄 안내하고 멈춘다
     (새 대화에 블록을 붙이면 오케스트레이터가 독립 Q-Gate를 수행한다)
   - `[RT-RETURN]`과 보완본 → Round 2 (아래 절)
   - 문서 없음 → 문서를 요청하고 멈춘다
2. **독립성 자동 점검** — 레드팀이 스스로 판별할 수 있는 것은 판별한다
   - R1 새 대화: 이 대화 안에 검토 대상 문서를 **만들거나 고친 과정**(분석 단계 출력, 초안 작성·수정 요청)이 있으면 '미충족'
   - R3 다른 모델: 시스템 정보로 확인되는 **현재 모델명**을 패킷의 `author_model`과 대조한다.
     같거나 같은 기반 모델의 변형판이면 '미충족'. 어느 한쪽이라도 모르면 '미확인' → 사용자 선언으로 채운다
   - R2 프로젝트 밖: 판별할 수 없다 → 사용자 선언
   - 작성 맥락을 찾으려고 과거 대화를 검색하거나 프로젝트 지식을 뒤지지 않는다 — 그 자체가 R1 위반이다
3. **게이트 질문** (1회, 선택형) — 자동 점검표를 먼저 보여 주고 고르게 한다

   ```
   [사용 규칙 점검]  R1 새 대화: 충족/미충족  ·  R2 프로젝트 밖: 선언 필요  ·  R3 다른 모델: 충족/미충족/미확인 (현재: 모델명 / 작성: 모델명)
   ① 규칙 3개 충족 — 독립 검증으로 진행 (독립성 높음)
   ② 미충족을 알고 진행 — 독립성 중간·낮음으로 기록, 결과와 최종 보고서에 남음
   ③ 중단 — 프로젝트 밖 새 대화를 열고, 작성과 다른 모델을 고른 뒤 "red-team으로"와 함께 다시 붙여넣기
   ```
   - R1 또는 R3 자동 점검이 '미충족'이면 **①을 제시하지 않는다** (②·③만)
   - 사용자 메시지에 `[사용규칙 확인]` 줄이 체크돼 있고 자동 점검과 모순이 없으면 질문 없이 진행하고 선언을 기록한다.
     모순이 있으면 질문한다
   - 고르지 않고 "그냥 진행"이라 하면 ②로 처리한다
   - 독립 실행 모드: 점검표만 출력하고 ①(셋 다 충족) 또는 ②로 자동 기록한다. ③은 없다
   - 같은 질문에 [필수]·[권장] 결손 안내를 함께 싣는다 — 질문은 이 1회뿐이다
4. **검토 강도 판정** — 패킷의 `scale`·`reversibility`를 따른다. 외부 문서는 06의 강도 3단계 기준으로 판정하고
   애매하면 표준. 패킷 값보다 **낮추지 않는다**. 문서에서 One-way 근거를 찾으면 올리고 1줄 보고한다
5. **완료 정의** 3줄 명시: 카드 확정 / 강도별 06 완주 / 판정서와 `[RT-RETURN]` 출력

### Phase B. 결론 요약 카드 확정

- 패킷 모드: `card`를 그대로 쓴다. 카드와 초안 본문이 어긋나면 그 불일치를 지적(중대)으로 먼저 등록한다
- 외부 문서 모드: 06 설계 원칙 1의 카드(권고안 요지 / 확정 사실 / 핵심 가정 / 탈락 대안)를 문서에서 만든다
  - 채울 수 없는 칸은 "문서에 없음"으로 두고 `missing_in_document`에 올린다 — 빈칸 자체가 첫 지적이다
  - 탈락 대안이 없으면 "대안 검토 부재"를 지적으로 등록한다
- 카드를 출력한다. 이후 패널의 공격은 카드만 근거로 한다

### Phase C. 패널 실행

modules/06_critic-review.md를 로드해 강도대로 수행한다. 아래 특칙이 06보다 우선한다.

1. **공격은 카드만** — 06 원칙 그대로
2. **방어는 문서 원문 범위에서만** — 06 3단계의 방어 논리·보완책을 문서에서 찾아 쓴다.
   문서에 없는 근거·보완책을 레드팀이 지어내 방어하지 않는다. 문서로 방어되지 않으면 "문서상 방어 불가"
   (결재권자도 문서만 본다 — 문서가 스스로를 방어해야 한다)
3. **회귀는 권고로** — 판정관의 회귀 판정은 `ruling: 회귀 권고(단계·사유)`로 적는다. 실제 회귀는 원 대화가 한다
4. 탐색 결과는 해당 페르소나 지적의 근거로만 쓴다

#### 06 적용 해석

| 06의 문구 | 레드팀에서 읽는 법 |
|---|---|
| 00 단계로 자동 회귀 | `ruling: 회귀 권고(00 문제 정의)` |
| 해당 단계로 회귀 | `회귀 권고(단계명)` — 외부 문서면 해당 장·절 이름 |
| 04 차점 대안·탈락 대안 | 카드의 `rejected_options` — 없으면 "문서에 없음" 지적 |
| Phase A 규모 판별 결과 | 레드팀 Phase A의 검토 강도 |
| 05 보고서 Ⅴ장에 요지 수록, 패널 전문은 별첨 | 판정서 본문에 요지, 붙임에 패널 전문 |
| 05의 Go/No-Go 기준에 연결 | `unresolved`·`premortem_top3` |
| 04의 외부 모델 교차검증 결과 통합 | 패킷 `ext_crossval: 수행`이면 문서에 실린 결과를 카드 사실로 본다 |

### Phase D. 산출

1. 첫머리: 입력 준비도, **독립성 등급과 규칙 점검표**, 검토 강도, 현재 모델명
2. **판정서** (사람이 읽는 본문)
   - 판정 한 줄: 유지 / 조건부 유지(조건) / 회귀 권고(단계)
   - 본질 판정(페르소나 A): 적합 / 부분적합 / 부적합 + 근거
   - 지적 표: 심각도순(치명 → 중대 → 경미), 문서상 방어 결과, 요구 조치
   - 미해결(페르소나 E) 전건, Pre-mortem 상위 3, D의 아이디어, 문서에 없는 항목
   - 붙임: 패널 전문(압축), 탐색 결과
3. **`[RT-RETURN]` 블록** — 스키마는 references/rt_protocol.md 4절. 판정서와 다른 내용을 넣지 않는다
4. 말미 안내 2줄: "`[RT-RETURN]`을 원 대화에 붙여넣으세요." / "판정을 올리려면 보완본을 이 대화에 보내 Round 2를 받으세요."
   — 독립 실행 모드에서는 안내 없이 판정서와 `[RT-RETURN]`으로 끝낸다 (`run_mode: 독립 문맥 자동`)
- 분량: 약식 1~2매 / 표준 3~5매 / 정식 8매 이내 (붙임 제외)

### Round 2 (같은 레드팀 대화에서만 — 독립 실행 모드는 `round: 2` 재호출)

- 기본 제공: 정식·One-way. 그 밖의 규모는 사용자가 요청할 때만
- 입력: 보완본 + 원 대화의 반영표(지적별 보완·수용)
- 대상: Round 1의 '문서상 방어 불가'·'미해결(조건부)'·잔여 리스크 대형 항목만 — 전 항목 재심 금지
- 이번에는 보완본이 방어 근거가 된다. 보완이 4요건(시한·지표·책임자·실현 근거)을 갖췄는지 페르소나 E 기준으로 본다
- 출력: `round: 2`인 `[RT-RETURN]` — 바뀐 항목과 최종 `ruling`만
- Round 3은 없다 (06 라운드 상한). 그래도 남는 항목은 잔여 리스크로 넘긴다

## 스킬 연계·경계

| 요청 | 담당 |
|---|---|
| 완성 문서의 독립 공격·판정 (새 대화·다른 모델) | **본 스킬** |
| 단일 결론을 처음부터 도출 | problem-solver (레드팀 경로를 고르면 본 스킬로 패킷이 넘어옴) |
| 쓰는 중인 계획·판단의 일반 검토 | judgment-core |
| 복수 과제의 예산·법률 타당성 스크리닝 | feasibility-review-loop-p4 |
| 계획 단계 간 정합 검증 (`[DATA-PN-OUTPUT]`) | planning-orchestrator Q-Gate |

- 원 대화의 작성 의도를 묻지 않는다. 문서가 말하지 않는 것은 문서의 결함으로 기록한다.
- 같은 대화에서 쓰라고 요청받으면 ①을 빼고 ②·③만 제시한다. ②를 고르면 독립성 '낮음'으로 진행한다
  (요청에 이미 "그냥 진행"이 있으면 묻지 않고 ②로 진행한다).

## 공통 금지 사항

- 독립성 등급을 실제보다 높게 적기 금지, 자동 점검과 모순되는 선택지 제시 금지
- 과거 대화 검색·프로젝트 지식 조회로 작성 맥락을 모으는 행위 금지
- 문서에 없는 방어 논리·보완책 창작 금지
- 문서 재작성·대안 재설계 금지 (06이 요구하는 D의 아이디어 1개는 예외)
- 페르소나 E의 미해결 항목을 임의로 해소 처리 금지, 없는 결함을 지어내 할당 채우기 금지
- 검토 강도 임의 하향 금지
