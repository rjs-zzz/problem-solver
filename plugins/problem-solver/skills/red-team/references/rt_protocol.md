# 레드팀 인계 규약 (RT 프로토콜)

problem-solver와 red-team이 주고받는 두 블록의 스키마와 처리 규칙.
원본은 저장소 `shared/rt_protocol.md` — 각 스킬의 `references/`로 복사된다 (`tools/sync_common.py`).

## 1. 왜 다른 대화·다른 모델인가

- 같은 대화에서 하는 검토는 작성 과정의 옹호 논리를 이미 알고 있다. 06의 "카드만 본다"는 원칙이 연기에 그친다.
- 같은 모델로 하는 검토는 작성할 때와 같은 오류를 공유한다(상관 오류). 모델을 바꾸는 것만이 이를 줄인다.
- 레드팀의 효과는 아래 **사용 규칙 3가지**에서 나온다. 규칙을 지키지 않은 검토는 "독립 검증"이라고 부르지 않는다.

## 2. 사용 규칙 3가지

| 규칙 | 내용 | 확인 방법 |
|---|---|---|
| R1 새 대화 | 작성한 대화가 아닌 **새 대화**에서 실행 | 레드팀이 자기 대화에 작성 과정이 있는지 스스로 판별 |
| R2 프로젝트 밖 | 작성 자료·초안이 지식 파일로 들어 있는 **프로젝트 밖**에서 실행 | 사용자 선언 (레드팀이 판별할 수 없음) |
| R3 다른 모델 | 작성할 때와 **다른 모델**로 실행 | 패킷의 `author_model`과 현재 모델 대조. 모르면 사용자 선언 |

- **같은 기반 모델의 변형판**(안전 장치·명칭만 다른 판)과 사고 강도(effort) 차이는 다른 모델로 보지 않는다.
- **독립 문맥 자동 실행**(7절): 별도 문맥의 하위 작업으로 레드팀을 띄우는 도구가 있는 환경에서는 새 대화를 여는 대신
  하위 작업 하나에 대상 문서만 넘겨 실행할 수 있다. 하위 작업은 작성 대화를 보지 못하므로 R1을 구조로 충족하고,
  작업 폴더·프로젝트 자료를 열지 않으면 R2도 충족한다. R3는 호출 측이 모델을 다르게 지정해야 충족된다.
- 레드팀 스킬은 SKILL.md 공통 형식이라 다른 회사 AI에도 설치해 실행할 수 있다. 스킬이 설치되지 않은 AI로 가져가면 레드팀 절차는 작동하지 않는다.
- 어느 경우든 다른 회사 AI로 문서를 옮길 때는 04의 외부 교차검증 패키지 규칙(기관명·인명 일반화, 금액은 구간·비율)을 따르고, 대외비 원문은 넣지 않는다.

### 독립성 등급

| 등급 | 조건 |
|---|---|
| 높음 | R1·R2·R3 모두 충족 |
| 중간 | R1 충족, R2·R3 중 하나 미충족 또는 미확인 |
| 낮음 | R1 미충족, 또는 R2·R3 모두 미충족 |

등급은 `[RT-RETURN]`을 거쳐 최종 보고서 Ⅴ장 머리에 그대로 실린다. 원 대화는 이 등급을 바꾸지 않는다.

## 3. `[RT-PACKET]` — 작성 측 → 레드팀

problem-solver가 「검증 경로: 레드팀」으로 진행될 때 05 초안 바로 아래에 출력한다.
다른 스킬·사람이 쓴 문서는 패킷 없이 문서만 넘겨도 된다 (레드팀이 카드를 직접 만든다).

```
[RT-PACKET]
meta:
  packet_id: RT-YYYYMMDD-nn
  source: problem-solver | 기타
  author_model: 작성 모델명 (모르면 "확인 불가")
  scale: 약식 | 표준 | 정식
  reversibility: Two-way | 부분가역 | One-way
  ext_crossval: 수행 | 미수행        # 04 외부 모델 교차검증
card:                               # 06 「결론 요약 카드」 — 00~05의 옹호 논리 금지
  recommendation: 권고안 요지 (5줄 이내)
  facts: [확정 사실관계 — 라벨 유지]
  assumptions: [{id: An, 내용, 확신도: 상|중|하}]
  rejected_options: [{id, 요지, 탈락 사유 1줄}]
target: 이 블록 바로 위의 보고서 초안 전문
rules_declaration: |
  [사용규칙 확인] R1 새 대화 ☐ / R2 프로젝트 밖 ☐ / R3 작성과 다른 모델 ☐
[/RT-PACKET]
```

작성 규칙
- 카드는 06 설계 원칙 1의 카드와 같다. 보고서 본문에 없는 내용을 넣지 않는다.
- `author_model`은 지금 응답하는 모델의 이름이다. 추측으로 채우지 않는다.

## 4. `[RT-RETURN]` — 레드팀 → 작성 측

```
[RT-RETURN]
meta:
  packet_id: 패킷 값 | null (외부 문서)
  reviewer_model: 레드팀 모델명 | 확인 불가
  run_mode: 새 대화 수동 | 독립 문맥 자동
  author_model: 패킷 값 | 미기재
  rules: {R1: 충족|미충족, R2: 충족|미충족|미확인, R3: 충족|미충족|미확인}
  independence: 높음 | 중간 | 낮음
  intensity: 약식 | 표준 | 정식
  round: 1 | 2
ruling: 유지 | 조건부 유지(조건 명시) | 회귀 권고(단계·사유)
essence: {판정: 적합|부분적합|부적합, 근거 1줄}     # 페르소나 A
findings:
  - {id: RT-n, 출처: A|B|C(축)|D|E, 심각도: 치명|중대|경미,
     지적, 문서상 방어: 성립|불가|미해결(조건부), 요구 조치}
unresolved:                          # 페르소나 E 미해결 — 전건
  - {조건, 조기 경보 신호, 판단 시점}
premortem_top3:
  - {실패 시나리오, 조기 경보 신호, 대응 조치}
idea: {D의 대체·보강 아이디어, 권고: 채택 검토|참고}
missing_in_document: [카드를 만들 때 문서에서 찾지 못한 항목]
[/RT-RETURN]
```

## 5. 작성 측의 반영 규칙 (원 대화)

1. **판정을 뒤집지 않는다.** 원 대화가 할 수 있는 것은 두 가지다.
   - 보완: 근거를 추가하거나 조치를 구체화하고, 해당 지적에 "보완 반영"을 표기한다
   - 수용: 잔여 리스크로 명시하고 수용 논리를 1줄 적는다
2. `essence: 부적합` 또는 `ruling: 회귀 권고` → 지정된 단계로 회귀한다 (problem-solver는 00).
3. `unresolved` 전건 → Go/No-Go 조건에 반영한다. 임의로 해소 처리하지 않는다.
4. `missing_in_document` → 본문에 채우거나 "자료 없음"을 명시한다.
5. 판정을 올리고 싶으면(조건부 유지 → 유지) 같은 레드팀 대화에 보완본을 보내 **Round 2**를 받는다.
   Round 2는 정식·One-way에서만 기본 제공하고, 그 밖의 규모는 사용자가 요청할 때만 한다.
6. 최종 보고서 Ⅴ장 머리에 `검토 주체: 레드팀 (모델 / 독립성 등급 / Round n / 자동·수동)`을 적고, `[RT-RETURN]` 원문을 별첨한다.

## 6. 같은 대화에서 06을 돌린 경우 (내부 검토)

Ⅴ장 머리에 `검토 주체: 내부 검토 (작성 대화·작성 모델 — 독립 검증 아님)`을 적는다.

## 7. 독립 문맥 자동 실행 (하위 작업으로 띄우는 경우)

별도 문맥·지정 모델로 하위 작업을 띄우는 도구가 있는 환경에서만 쓴다. 없으면 1~6절의 수동 방식(새 대화)으로 간다.

### 호출 측 (작성 대화)

1. **모델 지정** — 지금 응답하는 모델과 **다른 계열**을 고른다. 같은 기반 모델의 변형판·사고 강도 차이는 다른 모델이 아니다.
   사용자가 모델을 지정하면 그것을 따른다. 다른 계열을 지정할 수 없으면 그 사실을 적고 진행한다 (R3 미충족 → 독립성 '중간').
2. **넘기는 내용** — 아래 머리말 + `[RT-PACKET]`과 초안 원문(또는 완성 문서 원문)만 넘긴다.
   작성 의도·설명·변호·요약을 덧붙이지 않는다. 덧붙이면 R1이 무너진다.

   ```
   [RT-DISPATCH]
   run_mode: 독립 문맥 자동
   author_model: 작성 모델명
   reviewer_model_requested: 지정한 모델명
   round: 1 | 2
   access: 작업 폴더·프로젝트 자료·과거 대화를 열지 않는다
   [/RT-DISPATCH]
   ```
3. **반송 처리** — 돌아온 `[RT-RETURN]`은 붙여넣기를 거치지 않고 5절 반영 규칙으로 바로 처리한다.
   판정서 전문은 별첨 파일(또는 보고서 별첨 절)에 보존한다.
4. **Round 2** — 보완본 + 반영표 + Round 1의 `[RT-RETURN]`을 `round: 2`로 다시 넘긴다 (새 하위 작업이어도 된다 —
   레드팀의 직전 판단은 `[RT-RETURN]`으로 이미 전달된다).

### 레드팀 측 (하위 작업)

- 사용자와 대화할 수 없으므로 게이트 질문 없이 자동 판정한다.
  - R1: 받은 내용이 `[RT-DISPATCH]` + 대상 문서뿐이고 작성 과정이 없으면 '충족'
  - R2: 스킬 파일 외의 파일·프로젝트 자료·과거 대화를 열지 않았으면 '충족'
  - R3: 자기 모델명을 알면 `author_model`과 대조한다. 모르면 `reviewer_model_requested`로 대조하고 '충족(호출 기록)'으로 적는다
  - 셋 다 충족이면 게이트 ①, 아니면 ②로 기록한다. ③(중단)은 없다
- 대상 문서가 없거나 비어 있으면 판정하지 않고 `[RT-RETURN]` 대신 결손 사유 1줄만 돌려준다.
- 공통 「산출물 저장」의 `outputs/` 탐색·저장은 하지 않는다 — 대상은 받은 원문뿐이고, 저장은 호출 측이 한다.
- 말미 안내("붙여넣으세요")는 쓰지 않는다. 최종 응답은 판정서 + `[RT-RETURN]`이다.
