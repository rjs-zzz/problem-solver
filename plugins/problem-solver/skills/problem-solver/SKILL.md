# Problem-Solver: 구조적 문제해결 마스터 스킬

업무 문제를 6단계(정의→구조화→진단→대안→결정→보고)로 해결하고,
최종 결론 전 다차원 비판적 검토(모듈 06)를 자동 통과시키는 파이프라인.

## 실행 통제 (공통)

- **범위 고정**: 요청 범위 그대로 산출. 단계·산출물 임의 추가 금지. 요청이 잘못됐으면 한 문장으로 지적한 뒤 요청대로 수행.
- **완료 정의**: Phase A에서 "무엇이 충족되면 이 단계가 끝인가"를 3줄 명시. 충족 시 추가 검증 라운드 없이 종료.
- **검증 원칙**: 결과 기준(전수 반영·커버리지·라벨 일관성·판정표)은 전량 유지 — 감사 대응 기록물. 절차적 재확인("다시 확인", "재검증 라운드")은 지시하지 않는다.
- **위임 상한**: 본 스킬의 「에이전트」는 역할 전환(내부 추론). 서브에이전트 스폰 금지, 검증 목적 위임 금지.
- **진행 보고**: 착수 1문장 / 진행 중에는 중요 발견·방향 전환·회귀 시에만 1~2문장 / 종료 시 결론 선행.
- **분량**: 규모 판정별 상한 준수. 필러 절·중복 요약·상투 문구 금지.
- **입력 점검**: Phase A에서 본문 「입력 점검표」를 대조한다. ① 대화·첨부·앞 단계 산출물에 이미 있는 항목은 다시 묻지 않는다 ② [필수]가 빠졌으면 실행 전에 빠진 항목만 1회 묶어서 묻는다 — 항목마다 '없으면 결과가 어떻게 달라지는지' 1줄을 붙이고, 빠진 [권장]도 같은 질문에 함께 싣는다 ③ [권장]만 빠졌으면 멈추지 않고 표의 '없을 때' 처리로 진행한다 — 승인 대기가 있는 규모에서는 계획과 함께 '있으면 정확도가 오르는 자료'로 1회 안내한다 ④ 사용자가 "없이 진행"을 지시하면 [가정]으로 채우고 결론에 '잠정'을 표기한다 ⑤ 산출물 첫머리에 입력 준비도(충분: 필수·권장 모두 확보 / 부분: 필수만 확보 / 부족: 필수가 빠진 채 진행), 입력 현황(확보·가정·미확보), '바뀌면 결론이 달라지는 입력' 상위 3개를 적는다.
- **민감정보**: 자료를 요청할 때 "개인정보·대외비는 가리고 올려 달라"를 1줄 고지한다. 입력에서 주민등록번호·환자정보·계좌번호 등을 발견하면 가린 뒤 처리하고 그 사실을 알린다. 외부 검색어에는 내부 안건명·금액·인명을 넣지 않고, 외부 모델에 넘길 자료는 기관명·인명을 일반화한다(금액은 구간·비율로).
- **최신 동향 탐색**: 본문 「최신 동향 탐색」 절과 references/frontier_scan.md에 따라 관련 신규 이론·연구·사례·제도를 1회 탐색해 반영한다. 실제로 연 출처만 싣고, 검색 수단이 없거나 생략했으면 그 사실을 적는다 — 기억으로 최신 동향을 지어내지 않는다.
- **표현**: 본문은 개조식과 표로 낸다. 도식·차트·한 장 요약·모션이 필요하거나 사용자가 시각화를 요청하면 visual-presenter 스킬로 넘긴다 (미설치 시 표와 개조식으로 대신하고 그 사실을 1줄 적는다).

## 입력 점검표 (Phase A에서 대조)

| 입력 | 구분 | 없을 때 | 산출에 미치는 영향 |
|---|:---:|---|---|
| 문제 진술 — 무엇이 문제이고 무엇을 결정해야 하는가 | 필수 | 질문 | 00 문제 정의 전체 |
| 비교할 선택지의 내용 (요청이 "A안 vs B안"·Go/No-Go 형태일 때) | 필수 | 질문 | 03 대안, 04 채점 대상 |
| 성공 기준 — 무엇이 되면 해결인가 | 권장 | 00에서 도출 [가정] | 04 가중치 — **권고안 순위를 직접 좌우** |
| 제약 — 예산 상한·인력·기한·바꿀 수 없는 규정 | 권장 | [가정], 실행 난이도 점수 [추정] | 대안 탈락 여부, 통제 등급 |
| 근거 자료 — 실적·견적·규정 원문·회의록 | 권장 | 비용·편익은 '정성' 모드, 원인은 가설로 유지 | 04 수치 산출 모드, 02 판정 등급 |
| 조직 유형·결재 주체 (`[조직 프로필]` 블록이면 충분) | 권장 | 일반 조직 기준 [가정] | 승인 경로, 이해관계자 맵 |
| 결정 기한, 되돌릴 수 있는지 | 권장 | 요청 문면으로 추정 [가정] | 규모 판정 (약식/표준/정식) |
| 보고 대상·분량 선호 | 선택 | 실무자 기준, 규모별 상한 | 05 보고서 톤 |

- 무입력 요청(문제 한 줄만 제시)에서도 [필수]가 문면에 있으면 묻지 않고 진행한다.
- 사용자가 준비물·입력 양식을 물으면 templates/intake_sheet.md 양식을 그대로 출력하고 멈춘다.


## 최신 동향 탐색 (본 분석 착수 전 1회)

- 절차·검증·출력 형식: references/frontier_scan.md (탐색 착수 시 로드)
- Phase A 계획에 탐색 축과 검색 횟수를 1줄로 넣는다. 결과는 00~06 전 단계의 공통 입력이다.
- 검색 횟수: 약식 2회 이내 / 표준 4회 내외 / 정식 6~8회. 긴급 유형과 "탐색 생략" 지시는 생략한다.

| 탐색 축 | 이 스킬에서 찾는 것 | 반영 위치 |
|---|---|---|
| 이론·방법론 | 이 유형의 문제를 다루는 새 분석 틀·의사결정 기법 | 00 재정의, 01 구조화 방법 선택 |
| 연구·실증 | 원인 가설·대안 효과에 관한 최근 연구·평가 | 02 가설의 근거, 04 편익·리스크 추정 |
| 사례·아이템 | 같은 문제를 푼 다른 기관의 사례, 새 도구·서비스 | 03 대안 풀 — '반영' 항목은 대안 후보로 1회 검토 / 06 페르소나 D의 입력 |
| 제도·정책 | 관련 법령·지침·평가 기준의 최근 변화 | 04 제약·통제 등급, 05 실행 설계 |

- 탐색에서 나온 대안 후보도 04 채점과 06 검토를 똑같이 거친다. 03의 교차 검색 의무(한계·실패 자료 병행)를 적용한다.
- 보고서: 표준·정식은 붙임 「최신 동향 탐색 결과」, 약식은 붙임에 2줄.

## 워크플로우 (필수 준수)

### Phase A. 접수 및 계획 [유일한 Confirm 지점]
1. 문제 접수 → 규모·유형 판별
   - 유형: 정형(선례·규정 존재) / 복잡(이해관계자 다층·인과 불명) / 긴급(즉시 대응)
   - 성격: 이탈형(정상→이상) / 창조형(신규 기획)
   - 규모: 약식 / 표준 / 정식 — 아래 「규모 판정표」 기준
2. 0~5단계 전체 실행계획을 개조식으로 제시:
   - 단계별 적용 방법론, 예상 산출물, 예상 보고서 규모(약식/표준/정밀)
   - 약식 판별 시: 00 재정의 1문장 + 04 간이판정 + 06 약식으로 축소 계획 제시
   - 확인 필요 정보: 「입력 점검표」 대조 결과 — [필수]가 빠졌으면 질문, [권장]이 빠졌으면 안내
     (모르는 것을 숨긴 채 판단하지 않는다)
   - 가용 수단 확인: 이 환경에서 쓸 수 있는 수단(웹 검색·법령 조회·파일 읽기)을 확인하고,
     할 수 없는 검증은 계획에 "검증 불가 — [확인 필요] 처리"로 적는다
   - One-way 판정 예상 시: 04의 **외부 모델 교차검증 수행 여부**를
     이 시점에 함께 확인 (미합의 시 미수행이 기본값 — 실행은 멈추지 않음)
   - 로컬 자료 요청: "이 사안과 관련해 보유하신 내부 자료(공문, 회의록,
     실적, 규정, 타 기관 자료 등)가 있으면 업로드해 주세요"를 능동 요청
3. 확인 질문·자료 요청은 이 시점에 **전량 일괄 제시** (실행 중 추가 질문 금지)
4. 실행 전 정지는 「규모 판정표」를 따른다 — 정식은 "이 계획으로 진행할까요?" 승인 후 진행
   (실행 개시 이후 00→06 전 구간을 **한 번도 멈추지 않고** 완주)

○ **[약식 자동 완주]** 약식 규모로 판정되고 [필수] 입력 결손이 없으면 승인 절차를 생략한다 —
  실행계획을 1문단으로 고지한 뒤 즉시 Phase B~D를 완주하고, 산출물 말미에
  "계획 변경이 필요하면 지시" 1줄만 남긴다. 승인 확인은 **정식 규모에서만** 요구한다.

#### 규모 판정표 (Phase A에서 잠정 판정 — 애매하면 표준)

| 규모 | 판정 기준 | 보고서 | 06 검토 강도 | 실행 전 정지 |
|---|---|---|---|---|
| **약식** | 되돌릴 수 있고(Two-way), 신규 예산·정원·대외 약속이 없으며, 부서 안에서 끝나는 결정 | 1~3매 | 패널 없이 5축 약식 + 스틸맨 1회 | [필수]가 빠졌을 때만 질문 |
| **표준** (기본값) | 약식도 정식도 아닌 일반 검토 사안 | 5~10매 | 5인 패널 1라운드 | 계획을 1문단 고지. [권장]이 빠졌으면 안내하고 답을 1회 기다린다. 빠진 것이 없으면 바로 진행 |
| **정식** | 다음 중 하나 — 되돌리기 어려움(One-way) / 다년도 예산 / 정원·조직 개편 / 대외 협약 / 이사회·상급기관 안건 | 15매 상한 (05의 '정밀 리포트') | 5인 패널 + 독립 스틸맨 (One-way면 2라운드) | 계획 제시 후 승인 필수 |

- 사용자가 규모를 지정하면 그것을 따른다.
- 표준의 정지는 승인이 아니라 입력 보완 기회다 — 사용자가 "그대로 진행"이라 하면 즉시 실행한다.
- 04에서 가역성이 Phase A 판정보다 무겁게 확정되면 규모를 올리고 1문장 보고한다. 내리지는 않는다.

### Phase B. 단계 실행 (완전 자동 — 무중단 원칙)
- 00 착수 전에 「최신 동향 탐색」을 1회 수행한다 (생략 조건이면 사유만 기록)
- modules/00 → 05 순차 실행. 각 단계 산출물은 보고서 별첨용 기록으로 쌓는다
  (파일로 줄 수 있으면 별첨 파일에, 채팅 전용이면 최종 보고서의 별첨 절에 압축 수록).
  채팅에는 단계가 끝날 때 1문장만 남기고, 최종 보고서와 같은 내용을 두 번 출력하지 않는다
- **[핵심 규칙] 실행 중 사용자에게 질문·선택지·자료요청·중간승인을
  요구하지 않는다.** 각 모듈 내 "사용자 질문", "확인 요청" 류 지시는
  아래 가정 전환 프로토콜로 대체 해석한다.
- **가정 전환 프로토콜 (질문 대체)**:
  ○ 실행 중 미확보 정보 발견 시 → 질문하지 않고 [가정 A1, A2...]로
    라벨링, 가장 개연성 높은 값으로 설정 후 계속 진행
  ○ 각 가정에 설정 근거 + 확신도(상/중/하) + 틀릴 경우 영향 1줄 기록
  ○ 전체 가정은 최종 보고서 부록 "확인 필요 사항·가정 목록"에 일괄
    수록 — 사용자는 완성본을 보고 사후 교정 지시
  ○ 이 방식이 "임의판단 금지" 원칙의 이행 방법이다:
    숨긴 판단은 금지, 명시된 가정은 허용
- **유일한 중단 예외**: 가정으로도 진행이 무의미해지는 치명적 차단
  (법령상 명백 불가, 문제 자체가 성립 불가) — 이 경우에만 1회 질문
- 부분 요청 시(예: "대안만 평가해줘") 해당 모듈만 로드
- 각 모듈 파일을 해당 단계 착수 시점에 로드:
  - modules/00_problem-framing.md — 문제 정의
  - modules/01_issue-structuring.md — 구조화·분해
  - modules/02_root-cause.md — 진단·분석
  - modules/03_options.md — 대안 도출
  - modules/04_decision.md — 평가·의사결정
  - modules/05_reporting.md — 보고·실행설계

### Phase C. 비판적 검토 (자동 실행, confirm 없음)
1. 최종 결론 도출 직전, modules/06_critic-review.md 로드
2. 「결론 요약 카드」 작성 후, 5인 반대자 패널(제1원리 사상가·
   순진한 아웃사이더·전방위 감사관(5축)·프론티어 크리에이터·
   전면 반대론자)이 카드만을 근거로 권고안 공격 — 지적→방어→판정
   왕복 (1라운드 기본 — **정식 규모 + One-way 결정**에서만 2라운드). 제1원리 사상가는 결론의 본질
   정합성(적합/부분적합/부적합)을 판정하며 "부적합"은 00 단계로
   자동 회귀시킨다. 전면 반대론자는 계획을 증거로 인정하지 않고
   실현가능성(기술·조직·일정)까지 검증하며, 미해결 항목을 반드시
   Go/No-Go 조건에 남긴다.
   5축(자원·내부·외부·시계열·Pre-mortem)은 전방위 감사관
   1인이 체계적으로 전개 (약식은 패널 없이 5축 약식 + 스틸맨 1회)
3. 치명적 결함 발견 시: 결함을 명시하고 해당 단계로 자동 회귀하여
   대안 보완 (회귀 사실을 사용자에게 보고)
4. 사용자가 결론에 불만족 시 "다른 방법으로 재실행" 지시 가능 —
   지시받으면 지정된 단계부터 다른 방법론·다른 경로로 재수행

## 스킬 연계·경계

### Phase 스킬(P1~P6)과의 경계 — 산출물의 성격으로 가른다
| 요청의 최종 산출물 | 담당 |
|---|---|
| 단일 결론 1건 (선택·가부·원인 판정·해결책) | **본 스킬** |
| 환경분석·현황진단·SWOT | env-scanning-loop-p1 |
| 미션·비전·목표 체계·OKR·KPI | goal-setting-loop-p2 |
| 전략과제·추진과제·대안 풀 발굴 | strategy-option-loop-p3 |
| 복수 과제의 타당성 스크리닝·예산/법률 검토 | feasibility-review-loop-p4 |
| 로드맵·추진일정·RACI·KPI 전개 | roadmap-design-loop-p5 |
| 환류·모니터링·성과점검 체계 | feedback-loop-p6 |
| 계획서 전체, 또는 2개 이상 Phase 연속 | planning-orchestrator |

- 판별 기준: "이 답의 최종 형태가 **하나의 결정**인가, **문서의 한 파트**인가".
  결정이면 본 스킬, 문서의 파트면 해당 Phase 스킬로 넘긴다.
- 경합 문구 처리: "타당성 검토"는 단일 안건 Go/No-Go일 때만 본 스킬이 맡고,
  복수 과제 스크리닝이면 feasibility-review-loop-p4로 넘긴다. "대안 만들어줘"는
  기존 선택지 비교면 본 스킬, 과제 풀 발굴이면 strategy-option-loop-p3.
  "기획안 잡아줘"가 계획서 성격이면 planning-orchestrator.
- 본 스킬 수행 중 특정 Phase 산출물이 필요해지면 그 Phase 스킬을 호출해 받아온
  뒤 이어간다 — 사용자에게 별도 요청을 되묻지 않는다.
- **역방향 인계**: Phase 스킬 작업 중 단일 판정을 위임받으면 약식 규모를 기본으로
  수행하고 `[DATA-PS-OUTPUT]`의 meta.return_ref에 호출 쟁점 키를 기록해 반환한다.
  Go 결정 후 실행계획이 필요하면 블록을 roadmap-design-loop-p5 입력으로 넘긴다.

## 상시 적용 맥락 (조직 일반)
- **조직 프로필 우선**: 대화·첨부·프로젝트 지침에 `[조직 프로필]` 블록이나 조직 정보가 있으면 아래 일반 기준보다 먼저 적용한다. 없으면 일반 조직 기준으로 진행하고 [가정] 표기
- 관련 법령·규정 체크: 소속 조직에 적용되는 법령·내부 규정·단체협약 —
  근거 없는 해석 금지, 출처 명시

  현업부서/지원부서/고객·수혜자 — 조직 성격에 맞게 재구성해 사용

  이사회 보고 등)이면 해당 리스크를 자동 점검
- 개인 사안(투자·구매 등)에도 동일한 정교 절차 적용 (맥락 체크만 생략)
