# Module 05: 보고·실행설계 (Executive Reporting)

## 목적
00~04의 결과와 06 비판적 검토를 결재권자가 판단·승인할 수 있는
완결된 보고서로 조립하고, 승인 즉시 실행 가능한 계획까지 담는다.
보고서는 '설명 자료'가 아니라 '결정 요청 문서'다.

## 주력 방법론
- 민토 피라미드 (Minto, The Minto Pyramid Principle, 1987):
  결론 선행 → 핵심 근거(3~5개) → 상세 하향 전개
- 정부 공식 보고서 양식 (행안부·기재부 표준 준용):
  개조식, 【 】 제목 체계, 단문, 명사형 종결, 핵심 굵게

## 예비 방법론
- SCQA 도입부: 결재권자가 사안 배경을 모르는 경우에 한해
  상황-갈등-질문 3~5줄로 맥락 선행 배치

## 실행 절차
1. **보고 규모 판별** (규모별 상한 준수 — 초과 금지):
   - 약식 보고 (1~3매): 정형·Two-way 결정
   - 표준 보고 (5~10매): 일반 기획·검토 사안
   - 정밀 리포트 (15매 상한): One-way·예산 수반·이사회 안건
   - 규모 무관, 첫 장은 '결론 + 결정 요청사항' 고정
2. **표준 목차 조립** (모듈 산출물 → 보고서 장 매핑):
   - Ⅰ. 보고 개요 (결론·건의사항 선행) ← 04 권고안
   - Ⅱ. 추진 배경 및 문제 정의 ← 00
   - Ⅲ. 현황 및 원인 분석 ← 01·02
   - Ⅳ. 대안 검토 ← 03·04
     (평가 결과 + 기각 대안 상세 사유서 필수)
   - Ⅴ. 비판적 검토 결과 ← 06
     · 기술 방식 필수: 리스크 → 보완책 → 잔여리스크 수용 논리의
       3단 세트 (보완책 없는 리스크 나열 금지)
   - Ⅵ. 실행 계획
   - Ⅶ. 행정 사항 (예산·승인 경로·협조 부서)
   - [별첨] 근거 자료 목록(등급 표기), 가정 목록(조건부 진행 시),
     미검증 사항, 채점 상세, 06 검토 상세
3. **실행 계획 작성**:
   - 단계별 조치·일정·담당(안) — 부분가역 결정은
     '가역 조치 선행, 비가역 조치 후행' 순서 반영
   - 마일스톤별 성공 지표 (00의 성공 기준과 연결)
   - **단계별 점검 기준 (Go/No-Go)**: 어떤 신호가 나오면
     다음 단계 진행 또는 중단·재검토하는지 명시
     (06 Pre-mortem의 조기 경보 신호와 연결)
   - 선행 의존관계: 승인·예산·인력 확보 순서
4. **결재 동선 설계**: 보고 대상별 버전 분리 필요 시 제안
   (부서장용 상세 / 기관장용 요약 / 이사회용 안건 서식)
5. **셀프 QA**: 결론-근거 정합성, 수치 일관성, 출처 누락,
   개조식 문법(단문·명사형 종결) 점검 후 산출

## 산출물
- 보고서 본문 (위 목차, 개조식)
- 옵션 (사용자 요청 시에만): 결재 대상별 파생 버전,
  구두 보고용 말씀자료
- 템플릿 참조: templates/report_short.md (약식),
  templates/report_full.md (표준·정밀)

## 조직 맥락 체크포인트
- 문서 서식: 소속 조직의 공문서 작성 규정 준용 (항목 기호 체계,
  붙임 표기, 쪽 번호) — 한국 공공기관이면 공문서 작성 편람,
  기재부·행안부 보고서 표준을 기본값으로 적용 가능
- 예산 수반 사안: 재원별 구분 명시, 편성 시기 캘린더 대조
- 이사회·상급기관 보고 사안: 조직 표준 서식 적용,
  기관별 추가 요건 미확인 시 일반 표준 서식으로 작성 후
  [가정] 표기, 부록 "확인 필요 사항"에 기재 (질문으로 중단 금지)
- 민감 표현 점검: 개인 귀책성 서술, 타 부서 비판성 서술 중화

## 금지 사항
- 결론을 마지막에 배치하지 말 것 (미괄식 금지)
- 06 비판적 검토에서 드러난 약점을 은폐하지 말 것 —
  약점과 보완책을 함께 쓰는 것이 결재 방어력을 높인다
- 실행 계획 없는 보고서 금지 — "검토하겠음"으로 끝나는
  보고서는 결정 요청 문서가 아니다
