# Module 01: 구조화·분해 (Issue Structuring)

## 목적
재정의된 문제(HMW)를 MECE하게 분해하여 분석 가능한
이슈 단위로 만들고, 검증할 가설을 배치한다.
큰 문제는 풀 수 없다. 작은 문제로 쪼개면 풀린다.

## 주력 방법론
- MECE 로직트리 (맥킨지 — Rasiel, The McKinsey Way, 1999):
  중복 없이(ME), 누락 없이(CE) 분해
- 트리 유형:
  · What 트리(요소분해) — 현황 파악형
  · Why 트리(원인분해) — 원인 규명형 (00의 가설 연결)
  · How 트리(수단분해) — 대안 도출형
- 주 트리 1개를 유지하되, 하위 가지에서 유형 전환 허용
  (예: Why → How). 전환 지점을 명시할 것

## 예비 방법론
- 민토 SCQA (Minto, The Minto Pyramid Principle, 1987):
  이해관계자 다층 구조로 트리 분해가 어려운 경우
  상황-갈등-질문 서사로 핵심 질문을 좁히는 데 사용

## 실행 절차
1. **트리 유형 선택**: 문제 성격에 맞는 주 트리 1개 확정
2. **1차 분해**: 최상위를 3~5개 가지로 분해 (MECE 검증 필수)
   - 분해 기준(cutting logic) 명시: 프로세스순/이해관계자별/자원별/시간순 등
3. **2~3차 분해**: 분석 가능한 최소 단위(leaf)까지.
   깊이 최대 3~4레벨 (과분해 금지)
4. **가설 배치**: 00의 가설(H1, H2...)을 해당 가지에 매핑
5. **우선순위 태깅**: 각 leaf에 영향도(상/중/하) × 분석용이성 표기
   - 모든 판정에 (잠정) 라벨 부착 → 02 진단 후 확정으로 갱신
   - 80/20 원칙으로 핵심 이슈 2~4개 선정
6. **분석 계획 수립**: 핵심 이슈별 필요 데이터·확인 방법 정리
   (미확보 정보는 [가정] 전환 후 계속 진행 — 질문으로 중단 금지)

## 트리 출력 표준 (시각화 금지 — 들여쓰기 개조식 단일 표준)
```
○ [문제] 부서 간 협업 문서 회신 지연
  - H1. 문서 유통 프로세스 문제
    · H1-1. 결재선 과다 (평균 5단계) [영향도: 상(잠정) / 용이성: 상]
    · H1-2. 문서 포맷 비표준 [영향도: 중(잠정) / 용이성: 상]
  - H2. 인력·역량 문제
    · H2-1. 담당자 겸직 과부하 [영향도: 상(잠정) / 용이성: 하]
```

## 산출물 (개조식)
## 【이슈 구조도】
### 1. 로직트리 (들여쓰기 개조식)
### 2. 분해 기준 및 MECE 검증 결과
### 3. 가설 매핑 (가설 ↔ 트리 가지)
### 4. 핵심 이슈 우선순위 (영향도×용이성, 전체 잠정 라벨)
### 5. 분석 계획 (이슈별 필요 데이터·확인 방법)

## 조직 맥락 체크포인트
- '이해관계자별' 분해 시 소속 조직의 이해관계자 맵 사용
  (예: 상급기관/경영진/노조/현업부서/지원부서/고객·수혜자)
- 규정·예산·인사 관련 가지는 근거 규정 번호 병기
- 타 부서 소관 이슈는 트리에 남기되 '협조 필요' 태깅

## 금지 사항
- MECE 강박으로 현실성 없는 가지 생성 금지
  (분해의 목적은 완벽한 분류가 아니라 해결 가능성)
- 데이터로 검증 불가능한 leaf를 핵심 이슈로 선정하지 말 것
- 트리를 표·다이어그램으로 출력하지 말 것
