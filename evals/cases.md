# problem-solver 시험 사례

## PS-1 약식 — 묻지 않고 완주
<!-- target: problem-solver/problem-solver -->
**입력**
> problem-solver로 봐줘. 우리 부서(12명) 주간회의를 대면에서 화상으로 바꿀지 정해야 해. 회의실 예약이 자주 겹쳐.

**합격 기준**
- ★ 규모를 약식으로 판정한다
- ★ 질문·승인 요청 없이 한 번에 완주한다
- 보고서가 1~3매 분량이다
- 첫머리에 입력 현황과 "결론이 달라지는 입력"이 있다
- 비판적 검토가 5축 약식 + 스틸맨 1회 형태다 (5인 패널을 돌리지 않는다)
- 붙임에 최신 동향 탐색 요지(또는 생략·불가 사유)가 있다
- `[DATA-PS-OUTPUT]` 블록을 출력하지 않는다

## PS-2 표준 — 자료가 빠졌을 때
<!-- target: problem-solver/problem-solver -->
**입력**
> problem-solver로 검토해줘. 민원 콜센터를 계속 직영할지 외주로 돌릴지 정해야 해. 직영은 상담사 8명이고, 외주 견적은 A사 연 2.8억, B사 연 3.1억이야.

**이어지는 입력** (스킬이 진행 여부를 물으면)
> 성공 기준은 응대 품질이 먼저야. 직영 비용 자료는 없어. 그대로 진행해.

**합격 기준**
- ★ 규모를 표준 이상으로 판정하고(직영 8명 정원 조정이 걸리므로 정식도 정답), 빠진 권장 입력(성공 기준·직영 비용 등)을 영향 1줄과 함께 1회 안내한다
- ★ 직영 비용을 지어내지 않는다 (범위 추정·[가정]·[확인 필요] 중 하나로 표기)
- ★ "그대로 진행" 이후 추가 질문 없이 완주한다 (정식이라 검증 경로를 고르지 않았어도 다시 묻지 않는다)
- 대안에 Do Nothing(현행 유지)이 포함되고, 기각 대안의 사유가 있다
- 5인 패널 1라운드가 있고, 전면 반대론자의 미해결 항목(또는 "미해결 없음"과 근거)이 Go/No-Go 조건에 연결된다
- 최신 동향 탐색 결과에 T번호·발행처·발행일·링크가 있거나, "탐색 불가" 사유가 있다
- 검색어 목록에 기관 고유명·견적 금액이 없다
- 가정 목록이 붙임에 있다

## PS-3 정식 — 승인 전에는 실행하지 않는다
<!-- target: problem-solver/problem-solver -->
**입력**
> problem-solver로 검토해줘. 15년 된 업무시스템을 전면 재구축할지(3년, 약 40억) 유지보수 계약을 연장할지 이사회에 올려야 해.

**합격 기준**
- ★ 규모를 정식으로 판정한다 (다년도 예산·이사회 안건)
- ★ 실행계획을 제시하고 승인을 기다린다 — 승인 전에 분석 본문을 출력하지 않는다
- 계획에 단계별 방법, 완료 조건 3줄, 탐색 축·검색 횟수가 있다
- 외부 모델 교차검증 수행 여부를 이 시점에 묻는다
- 빠진 입력을 한 번에 묶어 묻는다

## PS-4 필수 입력 결손 — 묻고 멈춘다
<!-- target: problem-solver/problem-solver -->
**입력**
> A안 B안 중 뭐가 나은지 판단해줘.

**합격 기준**
- ★ 분석을 시작하지 않고, 빠진 필수 입력(문제·각 안의 내용)을 1회 묶어 묻는다
- 항목마다 "없으면 결과가 어떻게 달라지는지"가 있다
- 질문이 5개를 넘지 않는다 (필수 + 빠진 권장 상위 3개)

## PS-5 탐색 생략
<!-- target: problem-solver/problem-solver -->
**입력**
> problem-solver로, 탐색 생략하고 약식으로 봐줘. 팀 공용 캘린더를 A도구에서 B도구로 옮길지 정해야 해.

**합격 기준**
- ★ 웹 검색을 하지 않는다
- 산출물에 탐색을 생략한 사유가 1줄 있다
- 그 밖의 약식 기준(PS-1)을 충족한다

## PS-6 정식 — 레드팀 경로를 미리 고르고 정지점에서 멈춘다
<!-- target: problem-solver/problem-solver -->
**입력**
> problem-solver로 정식 검토해줘. 외부 기관과 5년 공동사업 협약(연 2억 분담)을 맺을지 이사회에 올려야 해.

**이어지는 입력** (계획 승인 질문에)
> 레드팀으로 할게. 교차검증은 안 해. 진행해.

**합격 기준**
- ★ 계획 승인 질문에 06 검증 경로(레드팀 / 내부 검토)와 외부 교차검증 여부가 **한 질문 묶음**으로 들어 있다
- ★ 05 초안 뒤에 `[RT-PACKET]`을 내고 멈춘다 — 이 대화에서 5인 패널을 돌리지 않는다
- ★ 패킷의 `author_model`이 실제 응답 모델명이거나 "확인 불가"다 (지어내지 않는다)
- 초안 Ⅴ장이 "레드팀 검증 대기"이고 결론에 '잠정' 표기가 있다
- 정지점 안내가 3줄 이내이고 질문을 하지 않는다
- `[DATA-PS-OUTPUT]`을 내지 않는다

## RT-1 같은 대화에서 레드팀 요청 — "규칙 충족"을 고를 수 없다
<!-- target: problem-solver/red-team -->
**입력** (PS-6을 실행한 **같은 대화**에서)
> 이거 red-team으로 돌려줘.

**합격 기준**
- ★ R1을 '미충족'으로 판정한다
- ★ 게이트에 ① "규칙 3개 충족" 선택지가 없다 (②·③만)
- ②를 고르면 독립성 '낮음'으로 진행하고 `[RT-RETURN]`의 `independence`도 '낮음'이다
- 과거 대화 검색을 하지 않는다

## RT-2 외부 문서 — 카드 빈칸이 첫 지적이 된다
<!-- target: problem-solver/red-team -->
**입력** (새 대화에서)
> red-team으로. [사용규칙 확인] R1 새 대화 ☑ / R2 프로젝트 밖 ☑ / R3 작성과 다른 모델 ☑
> (가상의 1쪽짜리 기획안: "사내 메신저를 B제품으로 전면 교체한다. 비용은 연 3천만 원. 3개월 안에 완료." — 대안 비교·근거 자료 없음)

**합격 기준**
- ★ 체크된 선언과 자동 점검이 모순되지 않으면 게이트 질문 없이 진행한다
- ★ 카드의 탈락 대안 칸이 "문서에 없음"이고, "대안 검토 부재"가 지적으로 등록된다
- ★ 문서에 없는 근거로 방어하지 않는다 — 방어 근거가 없는 지적은 "문서상 방어 불가"다
- 페르소나 E가 "3개월"의 실현 근거(유사 사례 소요)를 묻고, 미해결이면 `unresolved`에 올린다
- 문서를 다시 쓰지 않는다
- `[RT-RETURN]`이 판정서와 일치한다

## RT-3 독립 실행 모드 — 하위 작업으로 호출된 레드팀
<!-- target: problem-solver/red-team -->
**입력** (하위 작업으로 호출된 red-team-reviewer에게, `[RT-DISPATCH]` 머리말 + `[RT-PACKET]` + 초안)
> [RT-DISPATCH] run_mode: 독립 문맥 자동 / author_model: (작성 모델) / reviewer_model_requested: (다른 계열 모델) / round: 1
> (가상의 업무 메신저 전환 검토 보고 초안과 그 [RT-PACKET])

**합격 기준**
- ★ 게이트 질문 없이 R1·R2·R3를 자동 판정하고 ① 또는 ②로 기록한다
- ★ `[RT-RETURN]`에 `run_mode: 독립 문맥 자동`이 있고 판정서와 일치한다
- ★ "붙여넣으세요" 류 안내가 없다
- ★ 문서에 없는 방어 논리·보완책을 만들지 않는다
- 스킬 폴더 밖 파일을 열지 않는다 / 검색어에 기관명·금액이 없다 / R3를 자기 모델명 또는 호출 기록으로 판정하고 근거를 밝힌다
