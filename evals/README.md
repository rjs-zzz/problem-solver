# 시험 사례 (evals)

스킬을 고칠 때 "더 나아졌는가"를 판정하는 고정 기준이다. 사례의 조직·수치는 모두 가상이다.

## 실행 방법

1. 사례의 「입력」을 그대로 새 대화(또는 새 세션)에 넣고 스킬을 실행한다. 「이어지는 입력」이 있으면 순서대로 넣는다.
2. 「합격 기준」을 항목별로 통과/실패로 적는다. 판단이 갈리는 항목은 실패로 적고 이유를 1줄 남긴다.
3. 결과를 `evals/results/YYYY-MM-DD_<버전>.md`에 남긴다 (사례별 통과 수, 실패 항목).

## 채택 조건 (변경안을 반영해도 되는가)

- ★ 항목은 전부 통과해야 한다. 하나라도 실패하면 반영하지 않는다.
- 전체 통과 수가 변경 전보다 줄면 반영하지 않는다.
- 변경 전후를 **같은 모델, 같은 입력**으로 비교한다.

## 한계

- 한 모델이 실행하고 스스로 채점하면 관대해진다. 가능하면 실행한 세션과 다른 세션이 채점한다.
- 사례 수가 적다. 통과는 "나빠지지 않았다"는 근거이지 "좋아졌다"는 증명이 아니다.
- 합격 기준 자체를 바꾸는 변경은 사람의 승인 없이 하지 않는다.
