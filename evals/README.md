# 시험 사례 (evals)

스킬을 고칠 때 "더 나아졌는가"를 판정하는 고정 기준이다. 사례의 조직·수치는 모두 가상이다.

## 실행 방법

1. 사례의 「입력」을 그대로 새 대화(또는 새 세션)에 넣고 스킬을 실행한다. 「이어지는 입력」이 있으면 순서대로 넣는다.
2. 「합격 기준」을 항목별로 통과/실패로 적는다. 판단이 갈리는 항목은 실패로 적고 이유를 1줄 남긴다.
3. 결과를 `evals/results/YYYY-MM-DD_<버전>.md`에 남긴다 (사례별 통과 수, 실패 항목).

### Claude Code 자동 시험

`claude plugin eval`이 사례를 실행하고 판정 모델이 채점한다. 사례 파일은 이 폴더의 `cases.md`에서 만든다.

```
python tools/build_evals.py
claude plugin eval plugins/<플러그인> --allow-tools WebSearch WebFetch
```

- 사례 머리 아래 `<!-- target: 플러그인/스킬 -->` 주석이 대상이다. 새 사례를 넣으면 이 주석도 단다.
- ★ 항목은 `must` 채점기(가중 2), 나머지는 `quality` 채점기(3분의 2 이상 충족), 스킬 발동 여부는 지표로만 본다.
- 시험 실행에는 파일 쓰기 도구를 주지 않는다 — 스킬이 산출물을 응답 본문에 내고 채점기가 그것을 읽는다.
- 「이어지는 입력」이 있거나 같은 대화를 전제하는 사례는 자동 시험에서 빠진다. 위 수동 절차로 시험한다.
- 실행은 사용량이 든다. 기본 1회 실행(`runs: 1`)이고, `--runs 3`으로 늘릴 수 있다.

## 채택 조건 (변경안을 반영해도 되는가)

- ★ 항목은 전부 통과해야 한다. 하나라도 실패하면 반영하지 않는다.
- 전체 통과 수가 변경 전보다 줄면 반영하지 않는다.
- 변경 전후를 **같은 모델, 같은 입력**으로 비교한다.

## 한계

- 한 모델이 실행하고 스스로 채점하면 관대해진다. 가능하면 실행한 세션과 다른 세션이 채점한다.
- 사례 수가 적다. 통과는 "나빠지지 않았다"는 근거이지 "좋아졌다"는 증명이 아니다.
- 합격 기준 자체를 바꾸는 변경은 사람의 승인 없이 하지 않는다.
